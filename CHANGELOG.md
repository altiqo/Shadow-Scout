Рост неравномерен: на рынках, где хостеры зарегистрированы в PeeringDB и RIPE (Дания, Чехия, Швейцария, Бельгия), он

### Подбор: лучшие провайдеры на каждую локацию
- Раньше список кандидатов резался до анализа по `(популярность, размер, название)` до лимита 25 на *все* страны вместе:
  с настройками мастера по умолчанию 49 из 74 подходящих провайдеров (GleSYS, Elastx, Oderland…) даже не анализировались,
  а Исландия, Хорватия, Ирландия, Бельгия оставались без вариантов. Теперь план кандидатов берёт лучших на *каждую*
  локацию (по кругу, начиная с самых «бедных»), а потолок анализа (`--limit`, по умолчанию 200) делится поровну.
- Результат — топ-N на локацию (`--per-location/-k`, группировка `--by-city`). Один провайдер попадает в «лучшие» не более
  чем в `--max-repeat` локаций (по умолчанию 1), пока есть альтернативы: «один и тот же хостер на разные локации» больше
  не заполняет выдачу. Раздел «Лучшие по локациям» есть в терминале и во всех форматах экспорта.
- **Двухфазный анализ**: быстрая проверка всех кандидатов по локальным данным (префиксы ipverse + списки блокировок, без
  лимитов API), полная (cheburcheck, ip-api, PeeringDB) — только у лучших на локацию (`--deep`, по умолчанию 3).
  Если лидер «просел» после полной проверки, его место занимает следующий и тоже проверяется.
- «Неизвестно» ≠ «нет»: trial/почасовая у автоматически найденных провайдеров не известны, и раньше фильтр отбрасывал их
  как «нет». Теперь «неизвестно» подходит, а `--strict` требует подтверждения. В таблицах: `✓` подтверждено,
  `~` определено автоматически, `?` неизвестно, `—` нет.
- Фильтр по стране учитывает страны *серверов* (`locations`), а не страну штаб-квартиры.
- Сортировка списка провайдеров больше не зависит от регистра (`GleSYS` после `servinga` — это было).

### База провайдеров
- **Автокаталог** (`providers_auto.json`, команда `shadow-scout harvest`): организации из PeeringDB и таблицы имён ASN с
  признаками хостинга, точные ASN, города ДЦ, размер по реальным префиксам, проверка сайта на VPS/почасовую оплату.
  Сети, уже попавшие в блок-листы, не берутся. Правила — `harvest/classify.py`, ручные правки — `data/catalog_overrides.yaml`.
- Таблица стран расширена (Балканы, микрогосударства, Азия, Америка, Африка, Ближний Восток).
- Ручная база проверена против живых данных (`verify-db`): 38 ошибок → 2. У 16 записей были неверные ASN (в BGP не
  анонсируются), у 22 ASN не находился вовсе, `terrahost` указывал на сеть Gigahost; у 56 ASN определялся нечётким
  поиском по названию — теперь везде явные `asns`. Удалены 23 записи без собственного адресного пространства (сайт провайдера живёт в чужой сети —
  вероятные перепродавцы) и дубли (Arsys и World4You — сеть IONOS). Исправлены размеры и почасовая оплата (Bahnhof, HOSTKEY, Oderland, Rackforest).
  Удалены (причина — сеть, в которой реально живёт провайдер, или невозможность найти собственный ASN):
  - Arsys: принадлежит IONOS, сеть та же, что у ionos
  - World4You: сеть IONOS, дублирует ionos
  - avoro: сайт за Cloudflare, ASN не найден
  - Baltic Servers: сайт в сети Cherry Servers (вероятно, перепродавец; см. cherry)
  - Deninet: сайт в сети Rackhost (вероятно, перепродавец)
  - DotRoll: собственного ASN не найдено
  - e24cloud: собственного ASN не найдено
  - Websupport Hungary (EZIT): сеть Websupport (см. websupport-sk)
  - Hostcreators: сайт в сети VNET (вероятно, перепродавец)
  - Hostico: сайт в сети GTS Telecom (вероятно, перепродавец)
  - Hosting4Real: сайт в сети Hostingway (вероятно, перепродавец)
  - Hosting90: сайт в сети dogado (вероятно, перепродавец)
  - Hostingpalvelu: сайт в сети Planeetta (вероятно, перепродавец)
  - ICN.bg: сеть SuperHosting.BG, дублирует superhosting-bg
  - Latnet Serviss: ASN не подтверждён
  - Louhi: сайт в сети UpCloud (вероятно, перепродавец)

- Новое поле `aliases` — прежние названия для сверки с держателем ASN.

### Проверка
- `shadow-scout verify <ip>` — проверка выданного IP до оплаты: адрес и его /24 в списках, ASN, cheburcheck, ip-api,
  TCP-пробы и TLS-рукопожатие с заданным SNI. Код возврата 3, если адрес заблокирован.
- `shadow-scout verify-db` — сверка базы с RIPEstat/PeeringDB и сайтами; код возврата 1 при ошибках.

- Тесты меню больше не требуют настоящего терминала (раньше все 9 падали в CI, pipe и Git Bash под Windows).

  а также проверки качества самих данных (размер базы, покрытие локаций, уникальность, корректность записей).

  зависящие от порядка запуска и прошлых прогонов).

- При выводе в файл/pipe потоки переключаются на UTF-8 (на Windows `✖`, `●` и кириллица падали на кодовой странице).
- Каталог упакован в пакет (`data/*.json`).
