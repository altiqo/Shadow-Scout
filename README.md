# Shadow Scout

Консольный инструмент для подбора **небольших VPS-провайдеров под VPN**, чьи сети с наименьшей вероятностью попадают под блокировки РКН. Собирает данные из открытых источников, считает оценку риска по десятку сигналов, показывает **лучших провайдеров на каждую локацию** и сохраняет отчёт в HTML / PDF / XLSX / CSV / Markdown / JSON.

## Что умеет

- **Мастер поиска** — страны/локации (с преднастроенным списком «низкого радара»: Швеция, Венгрия, Исландия, Финляндия, Норвегия, Балтия, Чехия, Австрия, Швейцария…), trial, почасовая оплата, цена, тип IP-пула (ISP/DCH), размер сети, допустимый риск. Результат — **топ провайдеров на каждую локацию** (страну или город): один и тот же хостер не занимает все локации подряд, пока есть альтернативы.
- **Большая база**: 121 провайдер в ручной базе (ASN сверены с живыми данными) + **автокаталог на 1 737 провайдеров** из 71 страны, собранный из PeeringDB, RIPEstat и сайтов самих провайдеров (с точными ASN, городами ДЦ и признаком «продаёт VPS»). Каталог пополняется командой `shadow-scout harvest`.
- **Двухфазный анализ**: быстрая проверка *всех* кандидатов по локальным данным (префиксы + списки блокировок), затем полная проверка (cheburcheck, ip-api, PeeringDB) только для лучших на каждую локацию — поэтому большая база не растягивает поиск на часы.
- **Оценка риска блокировки** по 12 сигналам с весами и уверенностью (см. ниже), вердикт «низкий / умеренный / высокий / критический», подробный разбор каждого сигнала, рекомендации.
- **Проверка выданного IP** (`shadow-scout verify`) — после выдачи сервера и до оплаты: сам адрес и его /24 в списках блокировок, cheburcheck, ip-api, достижимость с вашей машины (TCP, TLS с нужным SNI).
- **Проверка самой базы** (`shadow-scout verify-db`) — сверка записей с живыми данными: устаревшие ASN, несовпадение держателя, недоступные сайты, расхождения в условиях.
- **Интеграция с [cheburcheck.ru](https://cheburcheck.ru)** ([LowderPlay/cheburcheck](https://github.com/LowderPlay/cheburcheck)): проверка ASN и сайта провайдера через `/api/v1/check` — заблокированные префиксы, реестр РКН, жалобы пользователей за 14 дней. Можно указать свой self-hosted инстанс.
- **Локальные базы блокировок**: antifilter.download, antifilter.network, Re:filter, CDN-диапазоны. Пересечение считается локально по всем префиксам ASN, поэтому не упирается в лимиты API.
- **Проверка произвольной цели** — `AS12345`, IP или домен: инструмент сам определит ASN, holder и локацию.
- **Discovery** — поиск небольших локальных ASN в выбранной стране (RIPEstat `country-asns` + таблица имён ASN + PeeringDB): находит B2B/ISP-провайдеров, которых нет ни в одной базе хостингов.
- **Живые TCP-пробы** с вашей машины (полезно из РФ): достижимость сайта и выборки адресов провайдера.
- **Красивый TUI**: баннер, меню со стрелками, живой прогресс анализа, цветные таблицы и карточки отчётов.
- **Экспорт**: HTML (лучшие по локациям + сортируемая таблица + раскрывающиеся карточки), PDF (кириллица встроена), XLSX (лист «По локациям» + 4 листа), CSV, Markdown, JSON.
- **Широкие настройки**: прокси, таймауты, параллельность, включение/выключение источников, свои URL списков, веса сигналов и пороги вердиктов, TTL кеша, форматы экспорта по умолчанию.
- **Запуск одной кнопкой**: ярлык на рабочем столе для Windows / Linux / macOS.

## Установка и запуск одной кнопкой

Требуется Python 3.10+ ([python.org](https://www.python.org/downloads/), на Windows отметьте *Add python.exe to PATH*).

**Windows**

1. Скачайте/клонируйте репозиторий.
2. Запустите `launchers\ShadowScout.bat` — при первом запуске создастся виртуальное окружение и установятся зависимости.
3. Чтобы получить ярлык на рабочем столе: правый клик по `launchers\install-shortcut.ps1` → *Выполнить с помощью PowerShell*.

**Linux / macOS**

```bash
chmod +x launchers/*.sh
./launchers/shadow-scout.sh          # первый запуск ставит зависимости
./launchers/install-shortcut.sh      # ярлык в меню приложений / на рабочем столе
```

**Вручную (любая ОС)**

```bash
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e .
shadow-scout                                   # интерактивное меню
```

## Использование

Без аргументов запускается меню:

```
🔍 Поиск VPS-провайдеров (мастер)
🎯 Проверить провайдера / ASN / IP / домен / выданный IP
🧭 Обнаружение малых ASN по стране
📚 База провайдеров (в т. ч. сводка по странам и пополнение каталога)
🔄 Обновить списки блокировок
📤 Экспорт последнего отчёта
⚙️ Настройки
ℹ️ О программе
```

Команды для скриптов:

```bash
shadow-scout search -c SE -c FI --hourly -k 5 --export html,pdf      # топ-5 на каждую страну
shadow-scout search --low-radar --trial --max-risk moderate          # все страны «низкого радара»
shadow-scout search -c SE --by-city --strict --verified-only         # по городам, только подтверждённые условия и VPS
shadow-scout search -c IS -c HR --deep 0                             # только быстрая проверка (секунды)
shadow-scout verify <выданный-IP> --live --sni www.microsoft.com     # проверка выданного IP до оплаты
shadow-scout check AS42708
shadow-scout check glesys.com --live
shadow-scout check hostup --export pdf                               # id провайдера из базы
shadow-scout discover HU --max 80 --analyze --top 10
shadow-scout harvest                                                 # пополнить каталог (несколько минут)
shadow-scout providers --stats                                       # сколько провайдеров на каждую страну
shadow-scout verify-db --source curated                              # сверить ручную базу с живыми данными
shadow-scout update
shadow-scout export -f xlsx,md -o ~/reports
shadow-scout paths
```

Отчёты по умолчанию сохраняются в `~/ShadowScout/reports`.

## Как работает подбор

1. **Фильтры базы** (страны, цена, trial/почасовая, тип IP, размер, связи с РФ…) → список подходящих провайдеров. Условия trial/почасовая трактуются «мягко»: подтверждённое «нет» отсекает, **«неизвестно» — нет** (флаг `--strict` требует подтверждения).
2. **План кандидатов** — вместо обрезки списка «по алфавиту» берутся лучшие на *каждую* локацию (местные операторы, малоизвестные, с подтверждённым VPS), по кругу и начиная с самых «бедных» локаций; потолок анализа (`--limit`, по умолчанию 200) делится между странами поровну.
3. **Быстрая проверка** всех кандидатов: префиксы ASN (ipverse / RIPEstat) и пересечение с локальными списками блокировок — без обращения к API с лимитами.
4. **Полная проверка** (cheburcheck, ip-api, PeeringDB, при желании живые пробы) — только у топ-N (`--deep`, по умолчанию 3) на каждую локацию. Если лидер «просел», его место занимает следующий, и его тоже проверяют; так лучшие в каждой локации всегда проверены полностью.
5. **Лучшие на локацию** — ранжирование по выживаемости с поправкой на полноту данных, «местность» оператора и подтверждённые условия. Один провайдер попадает в «лучшие» не более чем в `--max-repeat` локаций (по умолчанию 1), если есть альтернативы; пустую локацию повтором лучше заполнить, чем оставить. В общей таблице и карточках провайдер по-прежнему показан со всеми своими локациями.

Обозначения в таблицах: **Trial / Почас.** — `✓` подтверждено, `~` определено автоматически по сайту (проверьте), `?` неизвестно, `—` нет. **Пров.** — `●` полная проверка, `◐` быстрая (без cheburcheck). `[авто]` — запись из автокаталога.

## Как считается риск

Каждый сигнал даёт нормализованный риск 0…1, итог — взвешенное среднее доступных сигналов × 100. **Выживаемость = 100 − риск.** Уверенность — доля веса сигналов, по которым удалось получить данные (если источник недоступен, он не штрафует провайдера, а снижает уверенность).

| Сигнал | Вес | Источник | Что измеряет |
|---|---|---|---|
| Пересечение с базами блокировок | 3.0 | antifilter, Re:filter (локально) | доля IPv4-пространства и префиксов ASN в списках |
| cheburcheck: ASN | 3.0 | cheburcheck.ru `/api/v1/check?target=ASxxx` | заблокированные префиксы / все префиксы |
| cheburcheck: сайт | 1.0 | cheburcheck.ru | домен провайдера в реестре РКН, подсеть сайта |
| Размер сети | 1.5 | RIPEstat / ipverse | число IPv4-адресов (маленькие сети — ниже радар) |
| Тип IP-пула | 1.5 | PeeringDB, ip-api, база | ISP/резидентный vs датацентровый |
| Популярность / масштаб | 1.5 | база | насколько массово хостер используется для VPN |
| Юрисдикция | 1.0 | `countries.yaml` | HQ и локации: низкий / средний / повышенный / враждебный радар |
| CDN-диапазоны | 1.0 | 123jjck/cdn-ip-ranges | префиксы внутри CDN (блокируются массово) |
| Связи с РФ / реестр РКН | 2.0 | база | российские владельцы, реестр хостинг-провайдеров |
| Жалобы пользователей | 1.0 | cheburcheck.ru | жалобы «не работает» за 14 дней |
| Живая TCP-проба | 1.5 | ваша машина | достижимость сайта/адресов провайдера |
| Фрагментация | 0.5 | RIPEstat | много мелких /24 — арендованные «грязные» пулы |

Жёсткие правила: ≥ 50 % адресного пространства в списках, большинство префиксов по cheburcheck, реестр хостеров РКН или сайт в реестре → вердикт «критический». Веса и пороги меняются в настройках.

## База провайдеров

База состоит из трёх слоёв (приоритет при совпадении: пользовательские > ручная > автокаталог; дубли по ASN и домену сайта убираются):

| Слой | Файл | Что внутри |
|---|---|---|
| Ручная база | `shadow_scout/data/providers.yaml` | 121 запись: локальные провайдеры Скандинавии, Балтии, Венгрии, Чехии, Австрии, Швейцарии, Бенилюкса, Южной Европы, а также крупные хостеры для сравнения. Для каждого: **точные ASN**, локации, размер, популярность, тип IP, trial, почасовая, цена, способы оплаты, связи с РФ. |
| Автокаталог | `shadow_scout/data/providers_auto.json` | 1 737 записей: организации из PeeringDB с признаками хостинга, точные ASN, города ДЦ, размер по реальным префиксам. Сети, уже занесённые в блок-листы, не берутся. Условия аренды (trial, цена) не проверены, почасовая определяется по сайту. |
| Пользовательская | `providers.user.yaml` (путь покажет `shadow-scout paths`) | свои записи через меню «База провайдеров» или файл; запись с тем же `id` переопределяет встроенную. |

Каталог пересобирается на вашей машине командой `shadow-scout harvest` (результат — `providers.catalog.json` в каталоге данных, он перекрывает поставляемый). Ручные правки правил сбора — в `shadow_scout/data/catalog_overrides.yaml` (запретить/принудительно включить ASN, пометить связи с РФ, задать название).

Как собирается каталог: выгрузка PeeringDB (сети, организации, присутствие в ДЦ) и таблица имён ASN → правила по названию и типу сети (отсекаются IX, операторы связи, CDN, вузы, гипермасштабные хостеры) → префиксы и размер → отсев уже заблокированных сетей → **проверка сайта** (есть ли VPS/облачные серверы, упоминается ли почасовая оплата; русскоязычные сайты помечаются связями с РФ) → запись. Локации берутся из присутствия в ДЦ *в стране головной организации*: зарубежные точки пиринга не делают местного хостера «глобальным», иначе один и тот же провайдер всплывал бы во всех странах.

Цены и наличие trial меняются — проверяйте на сайте провайдера. `shadow-scout verify-db` сверяет записи с RIPEstat/PeeringDB и сайтами (CI запускает её раз в неделю).

## Источники данных

- [cheburcheck.ru](https://cheburcheck.ru) — [LowderPlay/cheburcheck](https://github.com/LowderPlay/cheburcheck) (API `/api/v1/check`, `/api/v1/status`)
- [antifilter.download](https://antifilter.download), [antifilter.network](https://antifilter.network)
- [1andrevich/Re-filter-lists](https://github.com/1andrevich/Re-filter-lists)
- [123jjck/cdn-ip-ranges](https://github.com/123jjck/cdn-ip-ranges)
- [RIPEstat Data API](https://stat.ripe.net/docs/02.data-api/) (префиксы, holder, поиск, ASN по стране, geo, abuse-контакты)
- [PeeringDB API](https://www.peeringdb.com/apidocs/) (тип сети, трафик, присутствие в ДЦ; массовая выгрузка для каталога)
- [ip-api.com](https://ip-api.com) (признак hosting/ISP)
- [ipverse/asn-info](https://github.com/ipverse/asn-info), [ipverse/asn-ip](https://github.com/ipverse/asn-ip) (названия и префиксы ASN, быстрый источник для массового анализа)
- DNS-over-HTTPS Cloudflare / Google для разрешения доменов

Все внешние запросы кешируются на диске (TTL настраивается). Если из вашей сети какой-то источник недоступен — укажите прокси в настройках или отключите источник.

## Важные оговорки

- Оценка **вероятностная**. «Чистый» IP не защищает от DPI-блокировок протоколов (TSPU). Используйте маскирующиеся протоколы (VLESS + Reality, Shadowsocks-2022, AmneziaWG, Hysteria2).
- Всегда проверяйте выданный IP **до оплаты** — `shadow-scout verify <ip> --live` и [cheburcheck.ru](https://cheburcheck.ru). Поэтому в фильтрах есть trial и почасовая оплата.
- Записи автокаталога — кандидаты, а не рекомендации: перед арендой откройте сайт и убедитесь, что VPS продаётся и условия вам подходят.
- Данные о провайдерах (ASN, цены, trial) могут устареть; инструмент показывает фактический holder ASN из RIPEstat и предупреждает о несовпадениях.

## Разработка

```bash
pip install -e ".[dev]"
pytest                  # тесты с мок-транспортом, без сети (в т. ч. меню без настоящего терминала)
pytest -m network       # проверки реальных API: формат PeeringDB / RIPEstat / ipverse
ruff check .
shadow-scout verify-db  # сверка ручной базы с живыми данными
```

Структура: `net/` — клиенты источников и индекс IP-диапазонов; `analysis/` — сигналы, скоринг, движок, discovery, проверка IP и базы; `selection.py` — план кандидатов и лучшие на локацию; `harvest/` — сбор каталога; `ui/` — тема, отрисовка, прогресс, меню; `export/` — форматы отчётов; `data/` — базы провайдеров и стран.
